# EuroDocBench

**1,440 synthetic European invoices in 12 locales and 5 layouts — PDF, scan,
text layer and exact ground truth — for benchmarking key-information
extraction and locale-aware normalisation.**

> **All documents are synthetic.** No real invoice is included, and the
> layouts are generated by five templates. A high score here shows that a
> system handles European number, date, VAT and identifier formats on clean
> generated documents; it is **not** evidence of accuracy on real invoices,
> and the keyword/regex baseline's 100 % exists only because it was written
> for these templates.

Built by [Since AI](https://sinceai.ai). Code, specification and scorer:
[github.com/sinceaihq/eurodocbench](https://github.com/sinceaihq/eurodocbench).
Browse documents and baseline predictions in the
[results Space](https://huggingface.co/spaces/sinceaihq/eurodocbench-results).

```python
# pip install "datasets[vision]"   (Pillow decodes the scan images)
from datasets import load_dataset

ds = load_dataset("sinceaihq/eurodocbench", split="test")
row = ds[0]
row["image"], row["text"], row["fields"]
```

## Task

Read an invoice (the `text` track uses the PDF text layer, the `scan` track
the `image`) and return 12 fields in canonical form:

| field | canonical form |
|---|---|
| `invoice_number` | as printed |
| `issue_date`, `due_date` | `YYYY-MM-DD` (`due_date` may be null) |
| `currency` | ISO 4217 (`EUR`, `SEK`, `DKK`, `PLN`, `CZK`) |
| `seller_name`, `buyer_name` | as printed |
| `seller_vat_id`, `buyer_vat_id` | country prefix + number, no spaces (`buyer_vat_id` may be null) |
| `iban` | no spaces (may be null) |
| `net_amount`, `vat_amount`, `total_amount` | plain decimal, e.g. `1234.50`; `vat_amount` is the total over all VAT rates (invoices with two rates print only the per-rate lines) |

Score with `eurodocbench-score --gold gold/test.jsonl --pred predictions.jsonl`
(see the [specification](https://github.com/sinceaihq/eurodocbench/blob/main/docs/SPEC.md)).

## Files

| path | content |
|---|---|
| `data/{dev,test}.parquet` | one row per document: `id`, `locale`, `language`, `country`, `layout`, `font`, `date_style`, `currency_style`, `image` (scan, JPEG), `pdf` (bytes), `text` (PDF text layer), `fields` (ground truth), `vat_breakdown`, `lines` (line items) |

## Splits

| split | documents | per locale × layout | seed |
|---|---|---|---|
| dev | 240 | 4 | 2026 |
| test | 1,200 | 20 | 2026 |

Locales: fi-FI, sv-SE, de-DE, fr-FR, nl-NL, it-IT, es-ES, pl-PL, pt-PT,
cs-CZ, da-DK, en-IE. Layouts: classic, modern, compact, grid, narrow.

## How the data was made

Everything is generated by code (`eurodocbench-generate --seed 2026`):
seller/buyer names from invented syllables plus a sector word and legal form,
real city names, line items from a translated catalogue, 2026 VAT rates,
amounts with commercial rounding, rendering with reportlab and the bundled
Liberation fonts, and simulated scanning (skew, blur, uneven exposure, noise,
JPEG). **VAT numbers and IBANs have the correct national format but
deliberately wrong check digits**, so they cannot belong to any real company
or bank account. No personal names appear.

## Intended use and limitations

For comparing document-AI systems on European formatting conventions. The
documents are single-page, template-based and cleaner than real invoices;
good scores here do not demonstrate real-world performance. Because the
generator is public, results of models trained on generated documents should
be reported as such; use a private seed for contamination-free evaluation.
