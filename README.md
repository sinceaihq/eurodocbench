# EuroDocBench

**A synthetic benchmark for extracting key fields from European invoices — in 12 locales, from born-digital PDFs and simulated scans.**

[![CI](https://github.com/sinceaihq/eurodocbench/actions/workflows/ci.yml/badge.svg)](https://github.com/sinceaihq/eurodocbench/actions/workflows/ci.yml)
[![Dataset](https://img.shields.io/badge/%F0%9F%A4%97%20dataset-eurodocbench-yellow)](https://huggingface.co/datasets/sinceaihq/eurodocbench)
[![Results](https://img.shields.io/badge/%F0%9F%A4%97%20results-browser-yellow)](https://huggingface.co/spaces/sinceaihq/eurodocbench-results)
[![License](https://img.shields.io/badge/license-Apache--2.0%20%2F%20CC%20BY%204.0-blue)](LICENSE)

Document-AI systems are mostly evaluated on English receipts and US-style
forms. European invoices differ in exactly the details that break automated
processing: `1.234,56 €` vs `€1,234.56` vs `1 234,56 €`, `05.03.2026` vs
`05/03/2026` vs `5. března 2026`, VAT breakdowns with several rates, local
VAT-number formats and labels in a dozen languages.

EuroDocBench isolates those details. Every document is generated by code, so
every label is exact; no real company, person, VAT number or bank account
appears. Systems read an invoice and return **12 fields in canonical form**
(ISO dates, plain decimal amounts, ISO currency codes, compact VAT numbers and
IBANs).

| | |
|---|---|
| locales | fi-FI, sv-SE, de-DE, fr-FR, nl-NL, it-IT, es-ES, pl-PL, pt-PT, cs-CZ, da-DK, en-IE |
| layouts | classic letterhead, banded "modern", label–value list, bordered grid, narrow receipt-style |
| tracks | **text** (PDF text layer) and **scan** (150 dpi greyscale JPEG with skew, blur, noise, compression) |
| fields | invoice number, issue date, due date, currency, seller and buyer name, seller and buyer VAT number, IBAN, net, VAT and total amount |
| splits | dev 240 · test 1,200 documents (balanced over locale × layout) |

Specification: [docs/SPEC.md](docs/SPEC.md) · technical report:
[docs/REPORT.md](docs/REPORT.md) · browse documents and predictions:

## Quick start

```python
from datasets import load_dataset

ds = load_dataset("sinceaihq/eurodocbench", split="test")
doc = ds[0]
doc["image"]  # PIL image of the scan
doc["text"]  # PDF text layer
doc["pdf"]  # original PDF bytes
doc["fields"]  # ground truth
```

Write one JSON line per document and score it:

```bash
pip install "eurodocbench @ git+https://github.com/sinceaihq/eurodocbench@v0.1.0"
# predictions.jsonl: {"id": "test-fi-FI-classic-000", "fields": {"invoice_number": "...", ...}}
eurodocbench-score --gold gold/test.jsonl --pred predictions.jsonl --markdown report.md
```

The gold files are in the dataset repository (`gold/test.jsonl`). The scorer
uses only the Python standard library.

## Generate your own (private) test set

The generator is deterministic. To evaluate without any risk of training-data
contamination, generate a fresh set with an unpublished seed:

```bash
pip install "eurodocbench[generate] @ git+https://github.com/sinceaihq/eurodocbench@v0.1.0"
eurodocbench-generate --out private --seed 739104 --dev 0 --test 20
```

## Reproduce the baselines

```bash
pip install -e ".[dev]"
python scripts/run_rules.py --data data --split test --source text --out runs/rules-text-test.jsonl
pip install easyocr llama-cpp-python
python scripts/run_ocr.py --data data --split test --out runs/ocr-test
python scripts/run_rules.py --data data --split test --source ocr --ocr-dir runs/ocr-test --out runs/rules-ocr-test.jsonl
python scripts/run_llm.py --data data --split test --source text --out runs/qwen2.5-1.5b-text-test.jsonl
python scripts/run_llm.py --data data --split test --source ocr --ocr-dir runs/ocr-test --out runs/qwen2.5-1.5b-ocr-test.jsonl
```

`python scripts/check_reproducible.py` regenerates a sample of the published
documents and compares them byte for byte with `releases/v0.1/manifest.json`.

## Limitations

Synthetic documents are cleaner and more regular than real ones: single
pages, no logos, stamps, handwriting or multi-page tables, and scan
degradation milder than many real scans. Results here measure locale handling
and normalisation; they are not evidence of performance on real invoices.
